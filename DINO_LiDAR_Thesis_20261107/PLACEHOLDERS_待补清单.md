# 正式公开前的待补清单

页面可以立即在本地预览。以下项目用于将交付的论文展示草稿补成你的正式主页；没有准备好的资源可继续保留待补状态。

## 论文与作者信息

- [ ] 确认正式英文论文标题，并统一网页大标题、浏览器标题、分享信息和引用中的标题。
- [ ] 填写作者姓名；如需要，将姓名链接到个人主页。
- [ ] 填写学校、院系或研究组的正式英文名称。
- [ ] 填写导师姓名及适当的主页链接。
- [ ] 确认毕业年份、学位类型及页面中的论文状态。
- [ ] 搜索 `index.html` 中的 `TODO`，逐项替换仍存在的占位信息。

## 文字与实验内容

- [ ] 逐段对照最终论文核对摘要、方法说明和贡献表述。
- [ ] 确认训练阶段与 LiDAR-only 部署阶段描述清楚，学生网络与 PIN-SLAM 地图语义 MLP 的角色一致。
- [ ] 核对每个结果数字、单位、指标方向、数据划分与对应论文表格。
- [ ] 保持 SemanticKITTI 验证序列 08 与测试序列 11–21 的区分。
- [ ] 核对轨迹图、ATE/RPE 及相关说明，确保结论与对应实验一致。
- [ ] 检查图片图注中的方法名、序列名与页面实际展示内容。
- [ ] 阅读 `sources/` 内的来源与素材说明，确认最终展示采用的文件版本。

## 图片、视频和分享预览

- [ ] 确认主视觉与方法图适合最终论文叙事。
- [ ] 确认分割、地图和轨迹图片中的文字在手机上仍能辨认。
- [ ] 如替换图片，保持文件路径与 `index.html` 中的引用一致。
- [ ] 检查分享预览图、favicon 及其链接。
- [ ] 若网页包含需要填最终站点地址的分享元信息，部署后填入实际 GitHub Pages 网址。
- [ ] 如准备演示视频，放入 `static/videos/` 或选定的外部平台，并填写对应入口。

## 资源按钮

统一在 `static/js/index.js` 顶部的 `RESOURCE_LINKS` 填写。

- [ ] **PDF**：加入最终论文 PDF，或填写学校论文库中的正式网址。
- [ ] **Code**：填入自己的论文代码仓库地址。
- [ ] **Video**：填入正式演示视频地址；如页面内还需直接播放，另行配置首页视频区域。
- [ ] **Poster**：加入正式海报；未制作时保留待补状态。
- [ ] 逐个点击确认链接能访问，文件版本正确，没有模板原作者的资源链接。

`static/pdfs/` 中的说明文件不是论文 PDF。只有真正放入论文后，才将按钮指向相应文件。

## 引用、致谢与来源

- [ ] 用最终题目、作者、学校和年份填写 BibTeX；毕业论文可使用适合学校要求的学位论文条目。
- [ ] 确认导师、合作方和项目致谢采用正式表述。
- [ ] 保留模板来源、许可和需要保留的致谢。

## GitHub 发布与最终检查

- [ ] 新建自己的 Public 网页仓库，并将网站文件夹内的内容上传到仓库根目录。
- [ ] 仓库根目录直接包含 `index.html`、`static` 和 `.nojekyll`；没有多套一层外壳目录。
- [ ] 上传的是解压后的文件，不是仅上传一个 ZIP。
- [ ] 设置 Pages 为 `Deploy from a branch` → `main` → `/(root)`。
- [ ] 等待 Pages Actions 成功，在最终网页地址检查电脑与手机布局。
- [ ] 点击资源按钮、导航、图片和引用复制功能，确认最终效果。

具体操作和常见问题见同目录的 `README_中文.md`。
